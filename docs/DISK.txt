The disk is meant to be very simple

[METADATA | DATA | SWAP ]
Are the major partitions of the disk.

Data is append only and bounded
Swap is something closer to a circular buffer, where data can be overwritten when it reaches the end, but also append
Metadata can be modified especially the HEAD pointer to the latest log entry's begin

The data is a recursive chunk based system.
Each chunk has a header and body, with a hash
"Files" are just a higher level concept managed by things like System.qa and Files.qa and typically map a URL to an ID
By folding all the chunks with that ID, you can get the file's data

The storage uses page alignment for each log entry with BULK entries for multiple different small chunks
Its quite easy to read and write a log entry as well as compact and GC
because you can just merge chunks, and mark those pages for deletion

The compaction is idempotent

The metadata is intended to be quite simple, with a few things like the version, write flag and commit flag (tells us if the log entry is complete or requires a rollback) and the HEAD pointer to the latest log entry's begin

Uses merkle trees for data chunks when compacting
